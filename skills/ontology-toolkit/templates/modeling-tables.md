# 三层建模表模板（Object / Link / Action）

> 使用说明：填写本模板时，保留首行斜体示例行供参考。每张表中的"假设"字段按「本体领航员」首轮响应铁律显式标注。

## 一、对象类型表（Object Types）

| 对象 | 英文标识 | 业务定义 | 关键属性 | 唯一标识 | 数据来源 | Owner |
|------|---------|---------|---------|---------|---------|-------|
| _设备（示例）_ | _Equipment_ | _已售出的在保/过保物理设备_ | _型号、出厂编号、保修截止日_ | _设备序列号_ | _ERP + MES_ | _设备主数据组_ |
|  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |

填写要点：
- 业务定义一句话说清"它是什么、为什么单独建它"，避免与相近对象重叠
- 关键属性区分原始属性（源系统直接同步）与派生属性（计算得出，注明计算逻辑）
- 唯一标识优先选业务主键；存在多源身份冲突时标注需做身份解析（Entity Resolution）

## 二、链接类型表（Link Types）

| 链接 | 基数 | 语义 | 支撑数据 |
|------|------|------|---------|
| _工单 —关联→ 设备（示例）_ | _N:1_ | _每张工单针对一台设备_ | _工单表外键 device_sn_ |
|  |  |  |  |

填写要点：
- 基数只允许 1:1 / 1:N / N:M；N:M 需注明中间关联对象
- 语义用业务动词描述（"拥有""包含""负责"），禁止写"关联表 fk_xxx"这类物理描述

## 三、动作类型表（Action Types）

| 动作 | 英文标识 | 执行者 | 校验规则 | 写回目标 |
|------|---------|-------|---------|---------|
| _升级工单（示例）_ | _escalateTicket_ | _值班主管_ | _优先级 P1 且超 4 小时未响应_ | _服务系统工单状态 API_ |
|  |  |  |  |  |

填写要点：
- 动作必须是"业务上真实发生的操作"，写回目标要精确到源系统的接口/表
- 校验规则写成可机判的条件表达式，不含模糊词（"尽快""必要时"）
- 每个动作需在备注中确认权限边界与审计要求

## 四、对象关系图

用文字化关系图表达（一行即可，多关系分行）：

```
客户 ──拥有──▶ 设备 ◀──针对── 工单 ◀──执行── 工程师
```
